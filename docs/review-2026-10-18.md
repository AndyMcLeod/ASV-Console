# ASV Console: review of the updates and feature additions, 2026-10-18

Andy: "Review updates and feature additions for entire ASV Console application. Once complete implement corrections
as you see fit. Generate a new report document in Word format." This is the report. It covers every change landed
since the 2026-10-16 bug and reliability review (`docs/review-2026-10-16.md`): 26 commits from `6f6cb0e` to the
tip `13e1398` (merged as `7dd2c69`), 61 files, 4,866 lines added and 639 removed. Each finding names the files and
lines as they stood at `13e1398`, before any fix; the Resolution section at the end says what each finding is now.
A Word rendering of this file sits beside it (`review-2026-10-18.docx`, made by
`node tools/review_to_docx.js docs/review-2026-10-18.md`); the Markdown is the source.

## Scope and method

What changed since the last review, by commit: the review's own 28 repairs (`32c2d94`) and its report; the way round
past an AIS contact held off the lines and the fuel rehearsal row (`7eed897`); the page thread moved off the chart's
work - the fuel walk every 10 s, two real windows, the seabed walk in a worker (`523632e`), the chart's layers drawn
in the chart worker and the route grid built twice as fast (`c66bd4f`); the controls window's watch on the chart
(`dae07fd`); the trail a sleeping chart missed, filled in, and an AIS contact's clear water (`fc095e5`); the SRC card
asking again on a partial answer (`e4f2664`); the units pill (`3dc594d`); the listen queue and the Edge-sleep banner
(`daa096d`); the cards moving only when the controls window closes (`367dd15`); the NOGO key (`c33c8cc`, `ae291c8`);
and the Canaveral work - a partial chart read used, the vessel's own unread water alone excused, a failed read refusing
to route, and the lock transit (`13e1398`).

Six reviewers each took an area: the chart read and the keep-out model; the lock transit; the planner changes; the
page's threads, workers and windows; the server and the Python modules; the tests and the documents against the code.
Each worked on a clean export of `13e1398`, was briefed from the code with the commit messages and handoff notes
named as claims to test, and was told to report only a defect it could show with a failing input or state, to
discard anything a suite already pins, and to prove a test's teeth by mutation. Every finding below was then verified
a second time by the author of this report - the reviewer's probe re-run, or the window traced through the code - and
repaired the same day with a check that fails on the code before the fix. A finding that did not survive that is not
here.

Baseline: a clean export of `13e1398`, all 154 suites run once sequentially, 0 failed. (A sweep of the working tree
the same evening had one red - `speed_zone_sources.py` 5c - which is finding 9: intermittent, and present on the code
before `13e1398`.)

Severity words as before: SAFETY (the planner or the autonomy does something the operator was told it would not),
RELIABILITY (a hang, a stall, a lost read, a race, a flaky check), WRONG BEHAVIOR (a wrong answer or advisory), DATA
(a file lost or corrupted), DOCS (a document claim the code does not bear out), TEST (a check with no teeth), MINOR
(a narrow window or a crafted input).

## Resolution (2026-10-18 and -19, the same session)

1. `lockTick` ends the exit stage once she is past the FAR gate by 0.8 x STANDOFF (nearer the way out's end than the
   far gate). lock_transit 6 ticks 60 m short of the far gate expecting "still exit", then 50 m past it expecting done.

2. THE TRANSIT OWNS NO RUN BUT ITS OWN LEG. `lockLegSent` notes `run_seq` before each leg is sent; the first running
   frame whose `run_seq` moved past it is the leg's motion, and a run that stops or pauses, or another motion (`run_seq`
   moved again: Stop, Hold, E-STOP, the guard's escape, an RTH, a Go-To, an Upload), ends the transit - the gates back
   unless she is inside the lock. `doGoTo` (not the transit's own leg), `doRTH`, `doUpload`, `doTransit` and
   `sailPassage` end a transit before they plan, so no plan is made on the waived model. GATE OPEN - GO IN waives the
   NEAR gate alone; FAR GATE OPEN - GO ON waives the far gate and puts the near one back. `lockTick` lifts a waiver
   whenever she is outside the lock unless the transit's own leg is taking her in or out. lock_transit 8 (a stale frame
